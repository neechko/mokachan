## About

Mokachan is a Discord bot that combines two main features: AI conversation with long-term memory (companion), and an automatic anime character claiming system inspired by Rimi-chan. All data is stored in the same single SQLite database, and new tables are created automatically the first time the bot is run, so no manual migration is needed.

## Features

### Companion AI (Token-Efficient)

The previous version resent five raw question-answer pairs to Gemini on every chat, causing the payload to grow larger as the conversation got longer. In this version, the AI feature uses a rolling summary and memory facts approach:

- Each request only carries: the system persona, one short summary, a few brief facts about the user, the last conversation turn, and the new prompt.
- The summary and facts are automatically regenerated by the AI every `SUMMARY_EVERY_N_TURNS` turns (default 6), via a single small Gemini call, rather than on every message.
- There's an affection point system that increases with every chat and influences the AI's speaking style. Use `mprofil` to view affection level, and `mresetcompanion` to reset the companion's memory.

### Anime Character Claiming

- As long as a channel is actively used for chatting, a random character from the AniList API (real anime/game data along with its image) will automatically spawn every `CHARACTER_SPAWN_INTERVAL_MS` (default 20 minutes).
- Whoever types `mclaim` the fastest gets the character.
- If no one claims it within `CHARACTER_SPAWN_TIMEOUT_MS` (default 10 minutes), the spawn expires and the channel can receive a new spawn.
- Rarity is calculated automatically based on the character's favorite count on AniList (Common / Rare / Epic / Legendary).
- Use `mkoleksi` to view the characters you already own.

### Song Lyrics (LRCLIB)

- The `mlyrics <song title> <artist>` command fetches song lyrics from LRCLIB (a public API, no API key required) and displays them directly in Discord.
- This feature is handled by `lyrics.js` at the project root (an old file, unchanged in this update).

## Installation

1. Upload the files from GitHub to your server's file manager.
2. Enter the project folder.
   ```
   cd folder-name
   ```
3. Remove old dependencies.
   ```
   rm -rf node_modules package-lock.json
   ```
4. Reinstall dependencies.
   ```
   npm install
   ```
5. Run the bot.
   ```
   node index.js
   ```

## Configuration

Update the `.env` file according to `.env.example` before running the bot.

**Required Variables**

| Variable | Description |
|---|---|
| `GEMINI_MODELS` | Comma-separated list of Gemini models, used as the fallback order, e.g.: `model1,model2,model3` |
| `BOT_NAME` | Bot name, e.g.: `mokachan` |
| `COMMAND_PREFIX` | Command prefix, e.g.: `m` |
| `COMMAND_CASE_INSENSITIVE` | Case-insensitive command matching, e.g.: `true` |

If your old `.env` still has `CMD_NYOMOXCHAN`, rename it to `CMD_MOKACHAN`.

**Optional Variables**

The following variables already have default values; see `.env.example` for details:

`SUMMARY_EVERY_N_TURNS`, `MAX_FACTS`, `AFFECTION_PER_TURN`, `CHARACTER_SPAWN_INTERVAL_MS`, `CHARACTER_SPAWN_TIMEOUT_MS`, `CMD_CLAIM`, `CMD_KOLEKSI`, `CMD_PROFIL`, `CMD_RESETCOMPANION`

## Migrating from a Previous Version

- The old database (`nyomoxchan_history.db`) is not carried over automatically. The new bot will create an empty `mokachan_history.db` file.
- To keep using your old history, rename the `nyomoxchan_history.db` file to `mokachan_history.db` before running the bot, or adjust the filename in `src/database.js`.
- All new data (companion memory, active spawns, character collection) is stored in the same SQLite database; new tables are created automatically the first time the bot starts.

## Network Notes

This bot calls two public APIs that don't require an API key. Make sure your hosting server has outbound internet access to both of the following domains:

| Feature | Endpoint |
|---|---|
| Anime character claiming | `https://graphql.anilist.co` |
| Song lyrics | `https://lrclib.net` |
